# Blind AI composition prompt check

The copied Markdown guide worked as a standalone composing prompt for **Grok 4.7 256K Extra High Fast** (`grok-4.7-xhigh-fast`) in three fresh CLI sessions on 16 November 2026. All three outputs passed on their first attempt, without host edits or compiler feedback.

| --- | --- | --- | --- | --- | --- |
| Glasshouse Waltz | main: 16 | 0 | 1 | 402.6 s | Pass |
| The Brass Observatory | explore: 16, combat: 16 | 0, 1, 2 | 9 | 683.8 s | Pass |
| Roots in the Archive | quiet: 24, alert: 24 | 0, 1 | 4 | 211.5 s | Pass |

Every score had zero compiler errors, compiler warnings, instrument-range findings, strong-beat harmony findings, random-note clashes and key findings. The host also checked the requested meter, key, instruments, cue names, loop lengths, layers, beds, random parts, transition fill, victory handover and new limiter make-up syntax where applicable. All 14 cue/intensity scheduler checks produced note events without errors.

## Method and access boundary

- Each request contained the exact [copied instructions](instructions.md), a complete music brief and a chat-only policy forbidding tools, files, source inspection, browsing and delegation. The composing instructions were not tailored between cases.
- The CLI ran in read-only Ask mode with its sandbox enabled, in a fresh empty workspace. Bubblewrap hid `/home/andre/code`, including the musicbox implementation. A separate preflight confirmed that `src/score.js` was not accessible at its repository path.
- All three completed CLI streams contained **zero tool calls**. The model received neither implementation code nor checker feedback. The host extracted each single score block verbatim from the terminal response.
- The initial harness failed before model invocation because its `/dev` mount prevented the CLI sandbox from starting. Fixing the device mount retained Ask mode, the enabled sandbox and repository hiding. Those startup failures are not counted as composition attempts.
- The host ran `musicbox check`, the compiler and full musical analysis, then exercised every cue and intensity with the real MusicPlayer scheduler, a fake audio clock and a recording synth. The current application suite also passed all 75 tests.

The exact prompt SHA-256 is `cde71c27ca18cee6b27214b3cf76d2bed68661614d6289365de0b5a37ec7b147`. It matches `docs/PROMPT.md` and the Markdown served to the Copy for AI button. The [manifest](manifest.json) records per-case prompt hashes, model ID, tool-call counts, timings and checker source hashes. Private thinking streams are excluded from these review artifacts.

## What the result supports

The guide is sufficient for this frontier model to produce complete, valid scores without source access, including features that must be learned from the supplied reference. The 3/4 waltz checked basic counting and instrumentation; the adaptive piece checked layers, transitions, a returning victory cue and `limit=-3,+1`; the ambient piece checked beds, arpeggiation, random notes and alternate patterns. No prompt repair was needed in this run.

This is evidence for the tested Grok model and these three briefs. Other model families, broad prompt robustness and subjective musical quality were not tested. The checks establish syntax and the measured musical constraints; they do not establish that the music sounds good. The pieces have not been independently listened to. The recommended workflow therefore retains checking and human listening after AI composition.
