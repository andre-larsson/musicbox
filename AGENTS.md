# AGENTS.md instructions for musicbox

<INSTRUCTIONS>
- Primary goal: musicbox, a plain-text score format and a Web Audio player for adaptive browser game music, forked from Scrimshaw (see NOTICE). Plain ES modules, no dependencies. Node 18+ for the CLI and tests.
- Repository: GitHub Pages project site, published at `https://a403.space/musicbox/` by `.github/workflows/pages.yml` on push to `main` (it runs the tests, then `npm run build`). After a push, check the Actions run and the live page.
- Git: commit straight to `main`. Pushing to `main` deploys the site, so push only when asked.
- Commands: `npm run check -- FILE.scrim` prints errors and warnings with line numbers, then an analysis; run it after every edit to a score. `node bin/musicbox.js link FILE.scrim` prints a listen link that opens the score in the live editor (add `--base http://127.0.0.1:5178/editor/` for the dev server), and `link --decode LINK` prints the score inside a link the user sends back. `npm test` runs the node:test suite (about 10 s). `npm run dev` serves the editor at http://127.0.0.1:5178/editor/ and reloads a score when its file is saved. `npm run build` writes the static site to `dist/`, and `npm run preview` serves it the way Pages does.
- Composing: read `docs/PROMPT.md` first; it is the format reference and the composing process. Agree the brief (scene, mood, tempo, key, cues, what each intensity layer adds, how cues hand over), plan the harmony lines before the notes, and use `:N` for notes longer than about four steps. For ambient or long-running cues, use the random parts and beds so the music doesn't repeat note for note. Check until there are no errors, and fix the analysis findings that aren't deliberate. Then give the user a listen link, ask them to try every cue and intensity level, and revise one pattern at a time from their notes. Don't regenerate the whole score.
- Code map: `src/score.js` parser and compiler (derived from Scrimshaw: mark changes with `musicbox:`, and any Scrimshaw score must compile to exactly the same events apart from slide sources, which `test/score.test.js` checks by hash; musicbox slides a `~` note from the note before it, where Scrimshaw used the voice's last note in the previous section). `src/synth.js` instruments, drums and beds (also derived). `src/player.js` `MusicPlayer`: notes are queued 0.3 s ahead, a cue switch happens at the first boundary after everything queued, each switch opens a new synth session so the old cue fades on its own bus, layers are per-voice gains, and beds belong to the player so they carry on across switches. `src/random.js` rolls random parts at play time with a seeded generator; the compiler keeps every choice (`pick` events, `loopSlots`/`introSlots`), except the arpeggiator, which the compiler expands. `src/analyze.js` the checker's report; random sets are checked with `rubs()`. `src/link.js` listen links (the score, raw-deflated and base64url-encoded, in `#score=`). `bin/` the CLI, the dev server and the build. `editor/` the editor page: `timeline.js` the seekable timeline (`player.seek`, `state.sections`), `master.js` the spectrum, meters and mix eq (it taps `synth.limiter` and calls `synth.setMixEq`), `dynamics.js` the gain, high pass filter, compressor and limiter controls (`synth.setMaster`; the filter is Butterworth sections from `highpassStages()`), `mastertext.js` reads and writes the score's `eq mix` and `master` lines (tested in `test/mastertext.test.js`). The `master` line's defaults (`masterDefaults()` in `src/score.js`) are the chain every score had before it, so scores without one sound the same. Web Audio reads a high-pass or low-pass filter's Q in dB; score Q values are the usual kind, so convert them with `biquadQ()` in `src/synth.js` (`test/filters.test.js` checks the responses).
- Notes: The editor runs under `/musicbox/` with no dev server, so keep its URLs relative; on Pages it reads `scores/index.json`, which the build writes. `scores/scrimshaw/` holds the upstream examples as regression fixtures; don't edit them. Every `scrim` code block in `README.md` and `docs/PROMPT.md` must compile cleanly (`test/docs.test.js`). Agents in other projects use musicbox through the musicbox skill and `npx -y github:andre-larsson/musicbox check|link`, so keep those commands working.
</INSTRUCTIONS>
